# S2Arm 通用方案经验 → NVN 接线层要用的参照与教训

用途：给 NVN 接线层（NVN → Ryujinx IRenderer → graphics/metal，绕过 Ryujinx.Graphics.Gpu）开工前读。SKILL.md 已写的接线专属坑（nxaot 缓存键、BindProgram 阶段位、视口带符号等）这里不重复。
每条格式：**规则**——为什么；出处。行号按接线分支 wire/silksong-c（10-23，= origin/main + 接线分支）与内部交接文档（未公开）当时版本。
出处缩写：坑 = docs/坑记录.md；方案 = docs/方案.md；调度 = docs/设计_帧级调度.md；越界 / 地址 / 零分配 / 接线 = docs/研究/Metal越界.md / 地址空间.md / 零分配与跨界.md / AI接线_C档_丝之歌.md；设计 = graphics/metal/设计.md；公约 / 契约 / 能耗21 / 能耗22 / 着色22 / 交接22 / 任务书 / 画幅要点 = 内部交接资料（未公开），只作出处记号，规则本身已写在条目里；abi = graphics/metal/gal_abi.h；契约 = tests/真机契约.md；visual = tests/visual/README.md；公约 = 交接/S2Arm_1021/开工公约.md；能耗22 / 着色22 / 交接22 = 交接/S2Arm_1022/帧率能耗线.md / 画面着色器线.md / 交接.md；能耗21 = 交接/S2Arm_1021/帧率能耗线.md；任务书 = 交接/S2Arm_1023/AI接线C档试点_任务书.md；画幅要点 = 交接/S2Arm_1023/C档试点_画幅线已读要点.md。

## 1. 环境与构建

- **产物根一律用私有克隆（clonedir.py 或 `cp -cR`），用 HEALTH_ROOT_<款> 指过去**——公共 roots/<款>@现行 会被出包轮换删除，A/B 打到一半根没了、归因作废；出处 graphics/wire/tools/wirerun.sh:6、能耗21:162、能耗22:80
- **shell 变量后面紧跟中文时一律写 `${VAR}`**——bash 3.2 在 UTF-8 下把全角字节读进变量名，set -u 直接退出；在 LC_ALL=C 下前半截进变量名、后半截被当命令执行；出处 坑:598-603、设计:205
- **带变量拼参数的命令写成 bash 脚本再跑**——Bash 工具是 zsh，不按空格拆 `$VAR`：tar 备份失败、删除照做，丢了 21 个脚本；两个 --env 拼成了一个参数；出处 坑:539-541、能耗22:211
- **破坏性动作写成「备份 && 核备份（大小 / 条数）&& 删」**——用 `;` 连接时备份失败，删除照样执行；出处 坑:541
- **两个下限都写在 tools/toolchain.env，只导出 MACOSX_DEPLOYMENT_TARGET，iOS 编译显式读它**——两个 *_DEPLOYMENT_TARGET 都导出时，宿主 clang 按 iOS 编；出处 坑:499-502
- **远端命令带上本机的 DEVELOPER_DIR**——否则按 xcode-select 缺省比工具链，门禁整份退回本机；出处 坑:494-497
- **离线着色器库 / 归档按 iOS 18 / macOS 15 下限编；链 SDK 27 的包必须走 UIScene**——按 SDK 缺省编的库老系统载不了；Xcode 27.1 包不接 UIScene，九款启动即崩；出处 设计:82-83、交接22:31
- **Metal 4 代码只写在 GAL_MTL4_ZONE 可用性区里，新代码只走 gal_be.h 入口**——tools/mtl4_count.sh 棘轮超过基线门禁就红；出处 设计:78-81
- **改 gal_abi.h 的签名 / 结构 / 常量后，C 与 C# 两端在同一个提交里重编**——ABI 指纹由 abi_hash.py 从头文件生成，旧库配新核心库曾越界卡死；出处 abi:8-9
- **Ryujinx 改动一律用 compat/patch_new.sh 出补丁并进改动清单；补丁号撞车时后合的一方改号**——门禁核「上游 + 补丁 = 树内源码」；三条线曾同时占用 0157；出处 公约:37、交接22:81
- **dotnet 工程构建一律加 `--artifacts-path <仓外目录>`**——否则会往 compat/tree 里写 obj；出处 visual:22
- **起局前在宿主二进制里搜改动独有的字样**——确认新代码真的编进去了；出处 公约:50
- **长脚本用冻结副本跑，出包树 / 跑局树里不提交、不合并**——跑到一半合并代码，读数作废；在出包树里提交会让包里的代码混版本；出处 公约:50、能耗21:215,257
- **读日志用 `LC_ALL=C /usr/bin/grep -a`；不要用 `| tail` 收尾**——本机 grep 是 ugrep；`| tail` 会吞掉退出码；出处 公约:50
- **吃内存的并行步骤按 S2A_CPU_BAKE 开路数**（tools/cores.sh 开工时按内存封顶算好）——不自己按核数开满，九款重烘约 48 GB 加上 Mac 局曾把整机吃满；出处 坑:3-10
- **给进程组发信号只走 tools/safe_killpg.sh**——算出来的组号变成 1 时会执行 `kill -KILL -- -1`，本用户全部进程被杀；出处 坑:36-43

## 2. Mac 局与测试工具

- **Mac 局只走 runtime/run_mac.sh（经 维护方工具 排队，全机 4 槽），带 S2A_CS=1 跑冻结宿主副本**；出处 公约:18、runtime/run_mac.sh:6
- **记住 Mac 局的上限：常驻 S2A_MEM_MB 缺省 16 GB、墙钟 = 秒数 + 30，一局 ≤300 秒**——超了直接杀并判红；出处 runtime/run_mac.sh:7、公约:46
- **暖局要复用缓存时显式给同一个目录；其余数据（Documents、Ryujinx 数据、着色器缓存）缺省放局目录私有**——落到共享的 Documents 目录时几局并行会互踩存档；出处 runtime/run_mac.sh:10-11
- **mac_health.sh 的 290 秒上限包含排槽时间，HEALTH_PAR 别超过空闲槽数**——排队的局会被直接杀掉；出处 能耗21:189、tools/mac_health.sh:3
- **Mac 游戏局不派到远端构建机**——它的内核在 64 GB 窗口里放了 2×12 GB 的 GPU 保留段，八方2 起不了局；出处 契约:92、公约:47
- **接线局 / 真值局都用 wirerun.sh 跑：同根、同参数、S2A_AUTOPLAY=0，只差 S2A_WIRE；真值局存帧窗口比接线局长**；出处 graphics/wire/tools/wirerun.sh:2-6
- **逐帧对比用出图层存帧 NXGAL_FRAME_CAP=a-b 或 mark+K:N，不用 galrec**——绕过 Gpu 层之后，两条路径唯一相同的是出图层；存帧格式 = 12 字节头 + 灰度；出处 graphics/metal/gal_present.m:475-476、画幅要点:7
- **判一致用 wire_cmp.py：8×8 块均值、单调对齐、连续 ≥3 帧超阈、接线局新增【红】行；先跑「通用 vs 通用」量出地板**；出处 tests/visual/wire_cmp.py:2-6、接线:88
- **framecap_check.py 只量闪帧和成片错位；整体被静态拉伸要拿 k=1 真值逐像素比**——静态拉伸每帧都一样，「帧间变没变」判据永远绿；出处 tests/visual/framecap_check.py:2-8、坑:452-454
- **galrec 录前清掉该游戏的 Ryujinx 着色器缓存，或用私有 S2A_RYU_DATA**——否则按二进制建的程序录不到 SPIR-V；接线局也经过 IRenderer，一样能录（S2A_GALREC / S2A_GALREC_FRAMES）；出处 visual:7、接线:91
- **galplay 用法：`--ref` 同步回放进 Vulkan@MoltenVK 参照，`--diff` 逐通道、`--diff-draw a-b` 逐绘制找第一处分歧**；出处 visual:8-9
- **只在重同步下出现、`--diff-nosync` 下没有的分歧，先当工具问题查**——D24 重同步写回不是恒等变换，造出 45 万像素的假分歧；出处 坑:545-548
- **判「我方不确定」之前先按比对点分两侧数哈希；不过的段同条件重跑一遍，复现了才判红**——下游两侧同变是重同步传播，不是独立来源；出处 坑:311-315
- **参照疑似有错时标「参照疑错」，交 Windows 真值仲裁；不为贴合参照改成错的**；出处 设计:55
- **对拍只证明两个后端一致，不证明和真机一致**——八方2 的体积查找表在两个后端上都是全 0，要拿 Windows 真值比；出处 设计:192
- **Windows 真值局跑同一份自动玩家和路线，按锚点取帧、不按墙钟；truth_cmp.py 分 8×6 格比 SSIM / 亮度 / 锐度**；出处 visual:11,24-30
- **单测里交给真 GPU 执行或读取的缓冲，分配后先清零**——新页恰好是 0 才能过，分配器复用旧内存时就卡死或中止；出处 坑:63-70
- **单测里两个判据可能同时成立时，只验一个，把另一个设成不可能触发；阈值要高于跑单测那台机器的调度抖动**；出处 坑:521-528
- **假设备的行为照真工具实测抄（含空对象 / 空串边界）；新流程在真机上跑通第一单才算上线**——真 devicectl 拒收 `'{}'`，假的照收，单测全绿；出处 坑:533-535
- **门禁 / 压测串行跑，跑门禁时本机不起 Mac 局**——负载叠加时渲染器单测超时、偶发红；出处 能耗22:4、着色22:175
- **偶发问题出现一次就抓栈，修复用确定性断言；不堆几十上百次压测，不靠多局撞概率**；出处 着色22:185、能耗22:278、交接/S2Arm_1020/新规_1020.md:10
- **偶发卡死先 sample 抓栈**——日志最后一行不等于卡点（进程被杀时没刷出的输出会丢）；出处 坑:67,70
- **iOS 包的托管帧符号化不可靠（ICF 折叠），只信原生帧；做法：解 ipa 后 `atos -l 0x100000000 0x1<偏移>`**；出处 能耗22:199

## 3. Metal 后端约束（graphics/metal）

- **除 nxgal_current_sync 外，所有 nxgal_* 入口在同一线程上调**——接线做法：游戏线程只录制，渲染线程回放成 IRenderer 调用；出处 abi:5、接线:54
- **双线程渲染缺省开，最外层是 Threaded(录像(宽屏(NxGal)))；非 GPU 线程直调下层的分支要持渲染线程锁**；出处 services/aot/Compose.cs:32-41、能耗21:175
- **渲染线程上不调任何会写客体内存的回调（计数结果 / 报告），回调放到计数线程**——写客体内存要拿写跟踪锁，持锁的线程可能正等着渲染线程，两边互等卡死；出处 坑:125-134
- **结果要写回客体内存的异步件（查询 / 报告 / 同步），由消费方自己等完成，不靠生产方「下一次」叫醒**——游戏可能正在 CPU 上轮询，不会再有下一次；八方2 因此停图后被看门狗自崩；出处 坑:282-287
- **GAL 同步号必须单调，由回放到那一刻的渲染线程分配；nxgal_current_sync 可在任意线程读**；出处 abi:71-74、接线:57
- **读回（GetData / GetBufferData）都隐含「提交 + 等 GPU」：缓冲读回只等自己的写（wfence），非渲染线程的贴图读回走后台队列**；出处 abi:81,118、坑:332-334
- **非渲染线程的读回不得占用主栅栏号**——曾导致延后释放提前放掉，命令缓冲引用失效资源；出处 设计:212-214
- **gal_transient 可能返回 NULL，调用方判空并跳过本条命令**——丝之歌 iPhone 第 24 帧往 NULL 写，崩了；出处 设计:33
- **资源建好就进驻留集，释放走 gal_release_later**——Metal 4 不自动驻留，漏登记就是 GPU 页错误；出处 设计:32、接线:68
- **内存池在首次被取址时才进驻留集**——小菠萝把 512 MB 未用的池整块钉页，4 GB 的机器被杀；出处 接线:65,68
- **零拷贝缓冲用 nxgal_buf_create_host / CreateBuffer(nint, size)；大于 4 MB 分窗，并过驻留安全阀**——旧架构驻留集整段钉 wired，造成内核恐慌；新架构 iPhone 探针三档 wired +0、逐字节核对无错；出处 设计:47,93-99、能耗22:267-269
- **零拷贝前提：CPU 写之前，先等「GPU 在用」这块缓冲的同步号**——去掉了 Ryujinx 原有的「回写前等 GPU」次序；估时 6–8 小时；出处 设计:100、能耗22:272-274
- **不在一条队列上 GPU 侧等另一条队列的事件；能在 CPU 上等就在 CPU 上等**——出图队列 waitForEvent 占住共用的渲染通道，整画面冻结恰好 4 秒；出处 坑:89-97
- **保留空闲保驻留心跳（主队列 300 ms 没提交，就提交一条 4 字节命令）**——GPU 空闲约 1 秒驱动就放掉整套驻留，长帧之后重钉不全，冻结 4 秒；出处 坑:100-106
- **命令缓冲任一出错即判红、写现场、`_exit(86)`；GPU 栅栏等待超过 3 秒判红退出**——丢掉的命令之后照常跑会产生次生缺页；本机 GPU 卡死可能触发整机看门狗重启；出处 设计:64-70、契约:89
- **记住 iPhone 的挂死阈值：片元单分块 11–17 ms，计算单批 0.44–0.50 秒（Mac 约 80 ms / 不杀）**——由数据决定次数的长循环一帧内就被判挂死；循环上限和越界钳位已在 gal_spvx 翻译里，同一份 SPIR-V 自动带上；出处 越界:29-31,43、方案:57
- **着色器越界是软缺页：读回 0、写被丢、不崩；真正的害是读到或写坏相邻分配**；出处 越界:19-24
- **NXGAL_BOUNDS_COUNT=1 只用来读计数，不拿来比像素**——插桩加了设备原子写，会改变苹果 GPU 上未定义行为的取值；出处 坑:47-52
- **同一时刻至多一个编码器；拷贝 / 计算 / 读回之前，gal_blit_enc 会自动收掉渲染通道**——遍内做不了的操作会切遍，附件整张存回再读入（iPhone 上是片外带宽）；出处 设计:31,34、调度:4
- **只在真依赖时切遍：输入来自本遍已画的才切；写的缓冲被本遍读过 → 换新块，不切；依赖判定先做精确（区间集）**——暗黑2 外包判定把每帧 211 次假依赖当真；出处 调度:20-32、坑:116-122
- **少开命令缓冲 / 编码器**——每个同时存活的带渲染遍的命令缓冲固定占约 2.3 MB，高水位不缩；每遍分段把暗黑3 的低区吃光；出处 坑:185-188
- **无附件渲染通道的宽高按各视口覆盖范围算，不按 1**——按 1 不崩不报错，只写缓冲的绘制只跑 1 个片元；出处 坑:169-174
- **贴图缓冲和普通贴图分两张绑定表**——同一绑定号先后绑两种，后绑的顶掉先绑的（八方2 酒馆全暗）；出处 坑:320-323
- **返回编码值的函数不拿 0 当失败**——R8Unorm 的描述编码恰好是 0；GAL Format 0 就是 R8Unorm；出处 坑:164-167
- **先认清是哪个枚举：Gpu.Image.TextureTarget 和 GAL Target 编号不同（GAL 9 = Buffer）**；出处 坑:299、abi:27
- **带 @autoreleasepool 的函数，出参里的 ObjC 对象在池外持有；被 C# 线程直调的 ObjC 入口要包 @autoreleasepool**——否则悬空崩溃，或 Metal 缓冲不释放（多占 75 MB）；出处 坑:589-592、能耗22:79
- **iPhone A19 写 half 附件是 RNE，Mac 是 RTZ**——这类差在 Mac 对拍里看不到；出处 着色22:29,98
- **单测再开一遍 MTL_DEBUG_LAYER=1 MTL_SHADER_VALIDATION=1**——越界写只有校验层会断言；出处 设计:46,216-218
- **接线回答翻译器问题时，口径和出包一致：着色器能力按 iPhone 目标固定，不按本机查**——口径不同 → SPIR-V 不同 → 离线库不中；出处 设计:108、abi:59-61

**组合层与宽屏**
- **接线拿 Compose 组合好的 IRenderer；比对期间两边宽屏都关（k=1）**——两边宽屏规则不同就没法逐帧比；出处 services/aot/Compose.cs:22-41、接线:89、画幅要点:12
- **建程序时带全 ShaderInfo 资源布局**——宽屏层按资源表认「这个程序写哪些图像」；资源表是空集合时，派发既不补组数也不报红；出处 坑:231-233,440
- **在渲染线程上读缓冲用 CpuPeek（nxgal_buf_peek_cpu），不调 GetBufferData**——小绘制的读回会走 gal_finish，0100152000022000 读回因此变多；出处 Compose.cs:32、能耗22:286、着色22:187
- **「一帧」按命令流里的写入顺序认，不拿上屏调用当边界**——上屏和绘制在命令流里不对齐；出处 坑:150-153

## 4. 着色器与首遇

- **离线库按 SPIR-V 内容哈希（SHA-256 前 8 字节）查；iOS 上未命中即报红计数、不现编**——接线交出的 SPIR-V 只要和通用路径逐字节相同，离线库必中；出处 设计:43、abi:126、接线:77
- **首选直查包里的 shaders/shcache（Ryujinx 磁盘缓存），运行时零翻译；GraphicsConfig.EnableShaderCache 必须在 RegisterProcess 之前置 true**——缺省 false 就是磁盘缓存整个关掉；出处 接线:75、设计:106,110
- **NVN 代码去掉 0x30 字节 NVN 头 = Ryujinx 缓存里的客体代码；查「不在缓存」时，先分清是「没抽到」还是「抽到了没配进程序」**；出处 坑:175-183
- **首遇一律阻塞等编完，绝不跳过绘制**——跳过的若是写常驻状态的绘制，那份状态永久是垃圾（八方2 整屏青绿）；Ryujinx 也是后台编、用到时等；出处 坑:350-357、设计:58-59
- **首遇零延迟靠出包覆盖（管线归档 + 特化预热；通用链接版 10-30 删除，日志 0 次顶上）；判据看真机「管线归档未命中」0 条、阻塞现建 0**；出处 着色22:9-14
- **管线分两级建：基础管线留空片元输出，首遇按状态特化（中位 0.00 ms）；顶点自取让管线键去掉顶点布局**；出处 设计:162-163
- **离线把 vs × ps 组合配出来**——Metal 没有按阶段复用，每个新组合都要整份编（中位 25.9 ms）；出处 设计:118
- **保留启动时的通用组合预热表（742 → 791 条，含全写掩码 15）**——特化代价按单附件「格式 × 混合 × 写掩码」记、跨进程保留；混合组合靠运行时记录补表，新游戏头一次仍会漏；出处 坑:363-368,374-377、着色22:213
- **新增「启动时建内部管线」的入口，要包在 gal_pso_warming_push / pop 里**——否则冷启动会被记成首遇现建，首局格全红；出处 坑:423-427

- **开归档片之前先向低区账本申请，开了不关**——iPhone 上关片不还地址，「腾退」是假的；出处 abi:64-65、坑:144-146
- **改出包产物形态（函数常量、特化）当场整款重烘一次，看归档读数（0 KB 判红）**——applegpu-nt 不支持带函数常量又被特化的片元函数；出处 坑:56-62
- **翻译时插进去的辅助值（如 threadgroups_per_grid 派生值）尽早用完，或落到普通内存再读**——活过大循环会让 applegpu 在编码阶段崩；运行时现编失败不缓存，每次重编约 1.6 秒；出处 坑:81-86
- **后台编译统一走 gal_compile_bg**——MTL4 序列化器挂上后，异步建管线接口会段错误；写盘和同一编译器上的并发现编会撞车；出处 坑:379-387
- **新机制的可行性样例先做一个会红的反例**——链接版 [[visible]] 函数里 discard 不生效、隐式 LOD 固定取 0 级（通用链接版 10-30 已删）；出处 坑:390-399
- **跨版本存的表用客体代码指纹作键，派生键（SPIR-V 键）用的时候现算；「对上 N」为 0 时当红看**——翻译器一改，首用表就一个都对不上；出处 坑:567-570
- **继承别人算好的特化状态时，清掉当前翻译器已经不查询的位**——陈旧的「坐标归一化」查询让暗黑2 4052 个程序重翻，绘制线程等管线 216–374 ms；出处 坑:552-557
- **写「缺省答案」之前，先看翻译端拿这个值做什么**——QueryTextureIsBuffer 只用一位；接线回答翻译器问题同理；出处 坑:296-299
- **提前热要热到实化用的那一层（预读共享数据 / 解压 / 特化状态）**——Ryujinx 0100 让程序当帧才实化，预取没有提前量；0100152000022000 首帧实化 212 → 50.8 ms；出处 着色22:152,203,270
- **几何 / 曲面着色器在接线里遇到就报红**——渲染器 supportsGeometryShader=false，Ryujinx 转成计算着色器、且不进磁盘缓存；hs / ds 程序建不出来、不画；出处 设计:194-196
- **出包期改动只要产物逐函数等价已证就可缺省开；否则缺省关 → iPhone A/B**；出处 着色22:263
- **私有根着色器键带收集表后缀，用冻结收集快照（S2A_SHCOLLECT）出包；派局用 `env -u S2A_SCHED_DIR -u S2A_SHCOLLECT`**——正式局一跑键就变、整份重烘；继承的空调度目录会让局排进没人读的地方；出处 着色22:52-53,99,125
- **做实验包之前列清它的局会喂哪些自动收集器，做完核正式包有没有变**——实验包产物会经「局 → 收集 → 下一版正式包」静默回流，还会自我繁殖；出处 坑:476-482

## 5. 性能（GC、跨界、节拍）

- **跨界本身不花钱：iPhone 上 C 调 C#（UnmanagedCallersOnly）约 2.1 ns，SGT P/Invoke 0.47 ns；新 pthread 第一次进 C# 约 0.8–1 µs（只一次）**——花钱的是分配，以及跨过去之后做的事；出处 零分配:7,59-71
- **长寿对象表用无引用的 struct 数组**——gen0 / gen1 回收永远停全部托管线程，单次停顿随「老对象.字段 = 新对象」次数涨（1 千次 1.1 ms、1 万次 8 ms、10 万次 25 ms）；出处 零分配:8,86-94,169
- **前端对象放在预分配的 struct 数组里，客体对象内存里只写一个 32 位句柄**；出处 接线:53
- **GCgen0size=64MB 只当安全阀，不当主方案**——gen0 越大，最坏一次停顿越长（171 ms 对 35 ms）；出处 零分配:101
- **按闸门判据设计：MARK 后每帧 alloc_b ≤2 KB（60 帧）/ ≤4 KB（30 帧）；整局单帧 GC 停顿 ≤ 帧预算 25%（4.2 / 8.3 ms）；读回合计 ≤ 窗口 1%，单帧 ≤ 1 帧预算**——丝之歌 GC 整局最长 8.5 ms，已经略红；出处 契约:72-78、任务书:7
- **读 frames.tsv 前认清口径：alloc_b = 全进程 GetTotalAllocatedBytes(false) 差分；alloc_gpu_b 是编码线程，不是 GPU 模拟线程；gc_pause_us 第 0 帧是启动以来累计**；出处 契约:46,53,75、能耗22:83,85
- **零分配在 NativeAOT 上量**——值元组排序在 NativeAOT 下每次分配 48 B，JIT 下是 0；出处 坑:207-208
- **量分配时专门造一帧「比以往都大的输入」**——按最大上传长大的临时缓冲稳态是 0，换场景那一帧分配 44 MB；出处 坑:212-217
- **「按需建、按事件丢」的缓存要有按时间 / 使用的上限**——事件（删缓冲）不一定会来，稳态分配和内存一起涨；出处 坑:204-206
- **标了 SuppressGCTransition 的 C 函数里不加锁、不等待、不编译、不分配**——SGT 里忙等 100 ms，GC 被拖住 89 ms；出处 零分配:79,198
- **游戏线程少进 C#**——原生线程不在 C# 里时 GC 不等它，GC 期间进 C# 才会被挂住；出处 零分配:24-29
- **按频率分层、能批就批：线程同步留在原生层，显卡按提交批**——反例：按 5 字节碎写逐次跨界，一局 2039 万次调用；出处 方案:29-33
- **用 S2A_ALLOC_TRACE=1 拆分配；查到「每次几百 KB」的调用，在调用内逐步打检查点定位**——不靠读代码猜；出处 能耗21:94、坑:280
- **轮询式等待改成能共同等待的信号；游戏 yield 轮询要退避**——轮询既耗分配又耗唤醒；出处 坑:276-280、交接22:118
- **有周期期限的宿主线程（声音、出图节拍）在建线程时就定调度档**——声音线程用缺省 QoS，负载下整批丢周期；出处 坑:304-307
- **诊断开关：S2A_THR_CPU=<秒> 看真机按线程占核；NXGAL_PERF_TIME=1 看渲染器分段（计时本身占渲染线程约一成，只在诊断时开）；S2A_GPU_TIME 拆 GPU 模拟线程**；出处 设计:207-208、abi:252、能耗22:259-261

**帧节拍与上屏**
- **帧率按游戏请求的交换间隔跑，不传帧率；接线上屏复用「[gal] 帧节拍：交换间隔 N，每帧 X ms（F 帧/秒）」这一行，格式不改**——记分板取最后一行；出处 契约:10、能耗21:195
- **封顶靠背压生产端，不许算完就扔**；出处 公约:7
- **上屏照小菠萝做：WindowAcquireTexture 处阻塞等垂直同步，QueuePresentTexture 只入队并调 IRenderer.Window.Present；SurfaceFlinger 合成循环照跑**；出处 接线:48,65
- **帧率格优先看 disp_us（画面真正上屏的间隔，presentedTime 差）**；出处 契约:54、abi:256
- **满屏判据（「【红】出图未满屏」）在出图层，接线局照样会触发；判据要钉住样本等它好，不能「到点没好就跳过」**——负载下会整片丢样；出处 visual:21、坑:107-114
- **游戏自己的长帧不算进接线收益**——丝之歌约第 800 / 1330 / 3055 帧的 >100 ms 长帧是游戏侧晚交帧；首局格用同包热局同流程位置 ±30 帧做差分扣除；出处 画幅要点:13、坑:605-610
- **不拿 GPU ms 当开销**——iPhone GPU 会降频把帧时撑满，30 帧下 GPU ms ≠ 开销；出处 交接22:118
- **加诊断开关前先确认它改不改口径**——逐遍提交本身改了 GPU 状态，一款第一方动作冒险游戏逐帧 GPU 26.3 → 17.2 ms；出处 能耗22:335-337

**读回与写跟踪（接线后哪些不需要）**
- **不用照搬写跟踪 / 回写 / 同步读回，渲染目标也不回写客体内存**——接线绕过的正是这一层，NVN 语义不需要，这正是通用路径读回阻塞的来源；出处 接线:8,56
- **游戏 CPU 直接写进池里的贴图（不经上传接口），要做脏页跟踪，并按块线性解排布后上传**；出处 接线:56,118
- **GPU 写、CPU 读的结果（查询 / 报告 / 拷到缓冲 / 信号量），在游戏等的栅栏完成之前必须对 CPU 可见**——八方2 过曝 = DMA 读回的 1×1 亮度页读到旧值；写跟踪缺省只拦写不拦读；出处 能耗22:17-18、坑:572-577
- **接线的条件渲染要自己定做法**——渲染器不做主机条件渲染（nxgal_cond_begin 恒 0），Ryujinx 会退回 CPU 读查询内存、触发回写等 GPU；出处 能耗22:289
- **读回 / 同步类改动的收益只用 iPhone 读数判，Mac 只用来复现机制**——Mac GPU 快：同一机制一款第一方动作冒险游戏 iPhone 读回 17.7 s / 60 s，Mac 只有其 2–3%；出处 坑:593-596
- **读回类改动缺省关合入，iPhone 同包 A/B 达标再翻缺省；全局 READFLUSH 永不再考虑**——读时回写让真机读回 0 → 44 s；出处 坑:575-578、能耗22:60
- **后端「等」的粒度对齐上层已经做过的同步；诊断键里带线程**——否则调用链对、线程错；出处 坑:336
- **信号处理 / 缺页路径里一次判断只读一次共享状态（取快照）**——池脏页跟踪同样适用；出处 坑:580-585

## 9. 接线开发前必须知道的 10 条

1. **只绕过 Ryujinx.Graphics.Gpu，不造第二个 Metal 后端**——出图、录像、离线库、验证工具都在 IRenderer 层以下，照用；出处 接线:8-9
2. **游戏线程只录制，渲染线程按 GAL 单线程回放；渲染线程不写客体内存**——GAL 入口单线程；写客体内存要拿写跟踪锁，会死锁；出处 abi:5、坑:125-134
3. **交出与通用路径逐字节相同的 SPIR-V（直查包内 shcache）**——离线库按内容哈希必中；iOS 上未命中即红、不现编；出处 接线:75-77、abi:126
4. **首遇只许阻塞等编完，绝不跳过绘制**——跳过一次就可能把常驻状态永久写坏；出处 坑:350-357
5. **GPU 写给 CPU 的结果在游戏等的栅栏之前可见，由消费方自己等**——八方2 过曝、八方2 看门狗自崩都出在这里；出处 能耗22:17-18、坑:282-287
6. **稳态零分配、单帧 GC 停顿 ≤ 帧预算 25%，在 NativeAOT 上量；对象用 struct 数组 + 32 位句柄**——跨界约 2 ns 不是问题，分配才是；出处 契约:72-78、零分配:7-8、接线:53
7. **池首次被取址才驻留、大于 4 MB 分窗、保留空闲保驻留；不在 GPU 上跨队列等**——这几处的教训是内核恐慌和 4 秒冻结；出处 设计:47、坑:89-106
8. **用出图层存帧 + wire_cmp 对通用路径真值比：k=1、同根同参数、只差 S2A_WIRE，先量「通用 vs 通用」地板**；出处 wirerun.sh:2-6、wire_cmp.py:2-6
9. **读数只认 iPhone 同包 A/B（ab.sh），能耗看 ≥3 局中位**——Mac 读回 / 同步收益推不出真机；同包波动可达 0.66 W；出处 坑:593-596、能耗22:252
10. **缺省关、报红不兜底、实验包走私有根 + 实验身份、只走列车合入，通用门禁全绿**——通用层一行不许改坏；出处 接线:11,99、坑:155-160、公约:36
