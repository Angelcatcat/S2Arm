# 丝之歌试点（10-23）实测经验

来源：本次会话 25 局 Mac 局的读数与修复记录。代码在 origin 分支 wire/silksong-c（已去游戏化）。

## 试点踩过的坑（每条都实测踩过；括号里是依据）
**构建 / 环境**
1. 新建的 C# 目录必须加进 `services/nxaot.sh` 的 SRCS 缓存键，否则改了代码不会重编，跑的是旧代码（10-23 白跑 3 局）。分支上已经加了 graphics/wire；再新建目录还得加。
2. NativeAOT 下用反射读不到 private const。改法：用 `compat/patch_new.sh` 把它改成 internal，然后直接引用（补丁 0197）。
3. 公共产物根会被换掉，必须用私有根（见第 1 步）。
4. zsh 里 `set -- $k` 不会按空格拆分；局脚本写成 bash 文件再跑。命令里也不要出现 `====` 这类会被 zsh 解释的字符。
5. Mac 上「管线归档不匹配 / 现建管线」是已知项（包里的归档只有 iOS 版），和接线无关。

**对象与命令语义**
6. 静态读出的「在用函数计数」只是下界。Unity 等引擎会把函数指针整批拷进自己的表，所以 BindVertexBuffers、DrawElements 这类必用函数的静态计数是 0。实现范围以「名字全集 + 运行时报红」为准。
7. 着色器控制段是游戏的临时内存，必须在 `ProgramSetShaders` 里当场拷走 0x880 字节。
8. `BindProgram(程序, 阶段位)` 是按阶段绑定的。Unity 会先绑含顶点 + 片元的程序，再调 `BindProgram(空, 0x3c)` 解绑其余阶段，不能当成整体替换。
9. 游戏传进来的 NVNtextureView 有些没经过 `TextureViewSet*` 初始化，所以视图结构里带魔数，读到没魔数的就按「无视图」处理。1D↔2D 的视图会让 Metal 断言崩进程，要在调用前拦住。
10. 缺省值一律逐个查 nvn.h，不凭记忆写（丝之歌写错过 3 处）：采样器 min = NEAREST_MIPMAP_LINEAR(4)、mag = LINEAR(1)、寻址 REPEAT(1)、比较函数 LESS(2)；深度模板缺省深度写开；混合缺省 ONE / ZERO / ADD；ColorState 透明测试缺省 ALWAYS(8)。
11. GAL 签名查源码再写：`DrawIndexed(索引数, 实例数, 首索引, 基顶点, 首实例)`。`ITexture.SetData` 的线性数据行要 4 字节对齐，否则报「写入数据不足」。NVN 的 3D 贴图目标值是 2（3 是 1D 数组）。
12. 剪裁框收到就下发（GAL 清屏按当前剪裁框裁剪）。组合贴图句柄在贴图槽和采样器槽都存完整值。
13. 栅栏的同步号由渲染线程在回放到那一刻时分配（GAL 同步号必须单调）。游戏线程这边先标记「待定」，`SyncWait` 先等它被赋号，再等 GPU 完成。

**方向与坐标**（全黑、偏移、颠倒的主要来源）
14. GAL 视口区域的高度带符号（Ryujinx StateUpdater.cs:775）。窗口原点左上时，视口用 `(x, y+h, w, −h)`，上屏**不**翻转（与通用路径 host.log「翻转 0/0」一致）；正面朝向对调 CW/CCW（StateUpdater.cs:1241）。
15. 交换链贴图可能比显示区域大（丝之歌是 1920×1080，只用左上 1280×720 的 crop）。翻转和裁剪组合错了，画面会整体偏移「贴图高 − crop 高」。
16. support buffer 按 Ryujinx SupportBufferUpdater 的写法填：ViewportInverse = (2/宽, 2/高（带符号）, 1, 0)；ViewportSize 取绝对值；深度模式写进 S2AFlags 的 `S2AFlagDepthMinusOneToOne` 位；渲染缩放全部为 1。

**着色器**（已在 WireShaders.cs 实现，新游戏一般不用动）
17. 绑定对照（小菠萝从游戏机器码全量实测）：用户常量槽 r ↔ c[3+r]；贴图句柄在 c[2][0x168+8r]，采样器句柄在 c[2][0x568+8r]；存储缓冲在 c[0][基址+0x10r]（顶点 0x110、计算 0x310、片元 0x510）。c1 = 代码块里 [控制段+0x700, +0x704) 那一段，零拷贝绑定。
18. SPH 阶段编码（Ryujinx ShaderHeader.cs:109）：0/1 顶点、2 曲面控制、3 曲面求值、4 几何、5 片元。
19. 同一份代码可能有多份特化（丝之歌是透明测试开 / 关两份），要按当前状态选（`WireShaders.Variant`）。计算着色器有一个口径坑：通用路径运行时带 0x100 字节头，出包工具是跳过这个头的；`ComputeHeaderSkipHits` 计数不为 0 就说明和通用路径不是同一份。
20. 离线自检的命中率偏乐观（包里的缓存就是用同一份抽取烘出来的），只认实局的命中 / 未命中计数。

**验证**
21. 两局通用路径本身逐帧不同，判据用 wire_cmp 的块指标 + 单调对齐；真值局存帧窗口比接线局长；两局都设 `S2A_AUTOPLAY=0`。
22. 接线局启动明显比真值局快（丝之歌快约 400 帧）。按帧号对比时要错开，或用 wire_cmp 自动对齐。

## 附录：已做过的游戏
- **丝之歌（Unity 2D，010013C00E930000）**：工作室标志画面与真值一致；标题画面只出了界面层。离屏链路是：世界画进 1280×720 目标 → 泛光（320×180 两张）→ 合成 → 调色这次绘制同时采样一张 256×4 的曲线查找表 → 界面层 → 拷到交换链。曲线查找表实测全 0，而且没有任何渲染目标画过它，嫌疑在 `CopyBufferToTexture`（源行距、视图级 / 层、区域 z，或者首用时被当成目标而跳过了上传）。其他 Unity 游戏很可能有同一条链路，**先查这一处**。
- 侦察已跑过（未接线）：马车 8、暗黑 2、巫师 3，名字全集分别是 479 / 527 / 536 个，包里都有着色器缓存。
