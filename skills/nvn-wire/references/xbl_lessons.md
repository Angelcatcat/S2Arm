## 一、对象与命令语义

- **宿主假冒的 NVN 结构一律 `_Static_assert(sizeof ≤ 真结构)`**——八方2 空贴图、巫师3 pc=0；游戏把 builder 嵌在自己对象里，SetDefaults 清零越界抹掉相邻字段（152 vs 64 字节）。坑:1955
- **老 SDK 游戏同时接管 `nvnQueueAcquireTexture` 和 `nvnWindowAcquireTexture`**——0100152000022000 / 0100000000010000建窗即空指针；真驱动把宿主窗口对象当自己的结构读。坑:1956
- **跨语言枚举按值换算，绝不强转**——录种子 600 秒缓存 0 个文件；nxgal 0 成功/1 失败/2 未完成 ≠ Ryujinx 0 Incomplete/1 Success，队头永远「未完成」卡死队列。判据 guest.toc 条数 = SPIR-V 落盘数（304=304）。坑:1946
- **未实现的 NVN 入口一律「首次被调报红」，再用全量日志数 0 条来证明不踩**——这是判「某语义要不要做」最便宜的射程（7105 份 boot.txt 0 条）；不报红的静默路径才是雷。同源:39
- **线性布局（位 4）/ 带行距的贴图初始化先报红一次，别静默建成空贴图**——无上传路径时不报错、画面缺块，最难查。同源:44
- **贴图对象会被游戏按值拷贝、在登记地址以外取用（47 万次里 12.4 万次）；别用对象地址做唯一键**，用序号或底层存储；同存储重建 / 销毁后取用要单独计数证明为 0。同源:19
- **引入「按地址建键的存储共用表」时，登记必须把脏页代号置新**——否则同地址重建的新池被误判干净、跳过首传。同源:40
- **计数回报 / 条件渲染同时实现**：时间戳会被写进计数格且异步写，只有条件渲染读这一格时才出错；接条件渲染时一起改。同源:42
- **从宿主调游戏函数，放到游戏自己调它的那个线程与时机（同上下文的 HLE）**——在出图 HLE 里调改分辨率函数主线程自锁；看门狗「等:锁 持有者=自己」= 放错地方。坑:440
- **SetLanguage 类「看似纯计算」的调用别剪**：剪前列出被剪调用树里的同步原语与对外副作用，必须为空——剪掉了条件变量 / 读写锁，间歇卡死。坑:53
- **按偏移读游戏对象字段前，先读原版谁写它、何时有效**；跨帧不留游戏对象裸指针（切布局 / 重建后成野指针）。坑:1657、坑:1823

## 二、着色器（翻译 / 缓存 / 首遇卡顿）

- **先数「深度测试开 + 不写深度 + 比较=EQUAL」的绘制数**；有就开 `-fpreserve-invariance`（metal -c 与运行时 options 都要），再 A/B——暗黑 30.5 万/124 万次走到，源码有 `[[position, invariant]]` 但全仓 0 处开关；营地 A/B 无可见差（差>32 的像素 0）。同源:58
- **预热种子清单按「首次使用顺序」存，不许排序**——按字母排后首帧前现建管线 2→30 条；前端在前、局内在后、真机追加在最后。坑:524
- **A/B 跳过冷起 loop0，或用「loop≥1 且 lib_new=0」判 warm**——loop0 的 lib_new/pso_new 不归零，会高估。活:35
- **管线归档在真机上用 iOS 着色器库收 / 编，不能拿 Mac 收的脚本**——同名 379 个 _b.metallib 两平台 SHA 0/379 相同，真机全未命中。坑:1938
- **Metal 4 管线归档按 iOS 大版本分别出，编归档机器 SDK ≥ 目标真机系统**——SDK 26.5 编的归档在 iOS 27 报 deployment target 不兼容，整开关失效。坑:1941
- **「跳过整段」的缓存指纹必须覆盖下游工具判新旧时读的全部输入**——运行时录到的整数属性 .attr 不进 iOS 库指纹，4 支顶点着色器永远按浮点读。坑:1931
- **种子局的游戏配置（宽屏、分辨率补丁）与 iOS 包完全一致，最好直接在真机录**；判据复跑局 `shader_miss = 0`——Mac 没开宽屏，iOS 多 1 支着色器每帧未命中。坑:1949
- **冷启动验证一律用全新解包的根**——克隆根 Metal 缓存是热的、无 DLC 弹窗；冷启动几千条管线同步编会让路线撞超时。坑:1929
- **缺管线跳过绘制时，路线「画面负载」同步点按「画出 + 跳过」计**，否则进世界绘制数被压低、同步点永远等不到。坑:1930
- **社区着色器缓存从 SPH 开始，我们切出的 .code 前面多 0x30 字节 NVN 外壳头（魔数 0x12345678），先剥掉**——0100152000022000 配上率 16/7037 → 6887。brotli 流要逐字节喂。坑:1945
- **Ryujinx 磁盘缓存与 NXGAL_SHLIB_DIR 按文件路径读，放 .app 内（只读），不进资源分卷**。坑:1947
- **上千个着色器 / 反射文件不用 `"$dir"/*.ext` 当命令参数，按目录 rsync；产物核对核到运行时要读的每一类文件**——CI 深路径通配超 ARG_MAX，6900 个反射 json 一个没拷，整屏粉紫。坑:1867
- **GPU 刀包出包加 `--metal-sources`，`zip -sf ipa | grep .metal` 确认**——否则没法现场改写着色器。活:39
- **改着色器的测量必须带结果已知的正对照（如「片元直接返回」）**——远端门禁机无 Metal 编译链，四局跑的全是旧着色器而不自知。坑:536
- **着色器生成规则写在规则函数体外会改代码指纹、触发全量重出**；改生成器前先确认指纹范围（6927 个里本只需 196 个）。坑:501
- **按着色器的 GPU 归因用 `SW_NVN_ENC_LABEL=1` 给编码器起名 + `SW_NVN_SKIP_FS` 逐个丢片元看该趟变化**——Shader Timeline 在远端门禁机拿不到。坑:517

## 三、贴图与格式 / 布局 / 上传

- **大量互不依赖的小 dispatch 用 `MTLDispatchTypeConcurrent`；量吞吐前先数 dispatch 次数**——缺省串行，数万次小网格让 GPU 空转在间隙；上传 113–195 → 49–52 ms，单帧最大 14.5 → 2.4 ms。坑:213
- **compute `setBytes` 不超过 4 KB**——超了驱动直接 abort，曾被误报成环境问题。坑:422
- **小浮点格式（RG11B10Float）的 CPU 参考按向零截断量化**——按就近舍入最坏差 5.9 步，截断后 1.9 步、九成逐位相同。坑:420
- **压缩贴图（BC*）读回用 blit `copyFromTexture:toBuffer`，别用 `getBytes`**——苹果驱动 TiledMemory convertTiles 崩。坑:448
- **游戏建贴图的格式可能来自别处的描述缓存而不是文件头；换格式（BC→ASTC）先找游戏真正读的那张表**——只改 .texture 头，游戏照按 BC3 建，满屏噪点。坑:1473
- **无 BC 设备：游戏把 BC 贴图整块拷进自己的纹理数组时，Metal 拷不了 ASTC→RGBA8，走计算核（copy_t2t_astc）**；格式表、块宽高按 NVN 格式查。坑:1473
- **自制 / 替换贴图做成原包同款格式（DXT5 + Tegra 块线性），用仓里的 nvn_swizzle/nvn_deswizzle 往返**——原始 RGBA 大图第 256 行起花点 / 竖条花屏，显存还 ×4。坑:1273、坑:596
- **上传暂存块换块时放掉旧块（含移出驻留集）**——每 4–8 次换图漏 32 MB；修前旧块落定后仍活着在驻留集。同源:12
- **改动「贴图序号 → 存储」对应（对调、换存储、原地合成）后，必带 `SW_RES_CHECK=1` 跑一局换区域的路线**——营地 / 菜单撞不到。坑:1140

## 四、渲染目标与通道（pass）

- **跳过游戏某一趟（外推帧、跳 FXAA、泛光 1/4）前，查清它的产物有没有被别的优化「改读」**——B0 从没被写过，外推帧读未初始化显存，只在 M4 上发绿。坑:1452
- **只在一种 GPU / 设备上出的画面错，先怀疑读了未定义内容（未写过、写回被丢），不是精度**。坑:1452
- **「读入可省 / 省写回」类探针的哨兵：浮点格式用 NaN，判红前换一个哨兵复跑看位置变不变**——half 单通道 65536 个值，真实输出撞哨兵出假阳性。坑:397
- **出图区域 / 呈现目标翻转那一帧，回放层照常写回，不记违规**——iPad 真全屏第一次换幕必出一行 xv 红，之后该附件永久失去省写回。坑:957、活:57
- **评估合遍先跑 `NXGAL_MERGE_WHY=1` 看「共用附件」行**——「相邻遍续用同一附件」46.5 次/帧多是同贴图不同 mip/层；真能合的 8.6 次里 86% 新组带新颜色附件（Metal 遍内不能加附件）。活:91
- **合并 / 推迟类优化按净账判：省下的 GPU 带宽与编码器 − 每帧所有通道都付的 CPU 规划成本**——tile 合并规划器每帧 +1.0 M 条指令只换来 3 次合并；改成预建索引二分、最便宜的否决最先做。坑:409
- **16 位深度目标上的 depth bias 常量单位不同（差 256 倍）、单采样目标开 alpha-to-coverage——先加一次性计数确认走不走得到，再决定改不改**（暗黑：16 位目标 69.5 万次、偏移开 0 次）。同源:59、同源:60
- **整帧调色 / 暗部曲线先读清后处理链每一步乘了什么、顺序如何；统计量先排除暗角与 UI**——曲线叠在暗角之后四角压成死黑；按亮场景定的曲线让暗场景 3D 均值 10.1→5.8，最终整段删掉。坑:496、坑:369
- **把常数换成运行时参数（分辨率等）后，用非原版取值跑一遍功能闸门**——编译器把「值域只有 1280/1600」折成了 `& 0x740`，切掌机后宽度变 768/64。坑:450
- **改游戏 3D 渲染比例必须主动触发一次重建目标，在游戏主线程取系统通知的 HLE 里调**——启动流程按输出尺寸直建，不调改分辨率函数。坑:440

## 五、同步、上屏与帧节拍

- **跨线程共享的 Metal 编码器 / 命令缓冲必须有所有者断言（`up_flush` 断言当前线程 == 提交线程）**——出图线程并发 endEncoding+commit，Mac 无窗口验收走不到出图线程，iOS 卡死主菜单。坑:230
- **涉及出图路径的改动用 `SW_WINDOW=1` 回放验**——Mac 无窗口拿不到图层提前返回，闸门对这条路径是盲的。坑:230
- **「登记」类小函数（驻留集 res_add 等）用自己的专用锁，不借业务锁**——借 g_mu 后在持锁的 arena_new 里自锁，单测 0.7 s → >300 s。坑:403
- **「Killed: 9 且无日志」先查 `os_unfair_lock` 重复加锁**。坑:521
- **节拍驱动出图的任何等待都要有超时兜底；`CAMetalDisplayLink` 停够 0.5 s 改自取 drawable 出图，3 s 后再试，间隔翻倍上限 60 s**——窗口被盖、整窗截图、音量键都会让系统停回调，画面定格 80 秒。坑:1844、坑:1204
- **截图别碰挂着节拍的 Metal 图层（drawViewHierarchy 后节拍会停）**。坑:1204
- **进后台：开「出图丢弃」时同时清掉已排队的帧，丢弃期间取图处不等旧票**——系统先停节拍后通知后台，交换链满时 acquire 等 present 无限等，存盘 0 次。模拟器 SW_TEST_BG 要先停节拍 0.15 s 再发事件才像真机。坑:1016
- **掉帧只认实际上屏间隔（`@presented_ms > 25 ms` 或 −1），出图调用间隔只做 CPU 归因**——按调用间隔报 833/1917 慢帧，上屏 >17 ms 实为 0。坑:336
- **换了出图 / 提交路径后，先用一个已知有差的开关验测量还能量出差**——Metal 4 后游戏循环恒 16.67 ms、与上屏解耦，两轮真机读数全是「−0.1%」。坑:484
- **Mac 无窗口回放只当定位工具，不出任何节奏类判据**——出帧间隔中位 3.4 ms，不是 60 Hz。坑:331
- **命令缓冲出错（ErrorHang / InnocentVictim / PageFault）一律判红、写现场、`_exit(86)`，不重建队列续跑**——被丢弃的命令里有上传 / 拷贝，之后的绘制读到没写进去的数据，故障扩散。坑:1972
- **MTL4 提交错误打 `error.description`（含 NSUnderlyingError），别只打 localizedDescription**——后者只说「超时」，底层是 GPU Address Fault。坑:430
- **宿主内核同步原语：先发布等待状态，再放锁**——svc 0x1C 先放锁后置键，SDK 用户态快路径读到 0 不唤醒，负载下丢唤醒；配确定性单测 + 旧序负对照。坑:81
- **宿主里「A 线程记下、B 线程用」的指针一律原子发布（atomic_store / atomic_load），且必上真机验**——Mac 时序巧合，真机读到旧值 0。坑:1245
- **热路径上「只记一次」先读后换**——原子交换判首例 = 每次命中写共享缓存行，三条录制线程抢一条，占主线程 5.3%。坑:1126

## 六、内存与驻留

- **Metal 4 不自动驻留：驻留集登记放在资源创建处（建出即 res_add），不放各调用路径**——首传漏登，进局后每次提交 GPU 地址页错误。诊断 `SW_RES_CHECK=1` 逐资源核。坑:425
- **延迟释放分「退役」与「只放引用」；视图缓存作废别把活着的基贴图移出驻留集**——原地合成对调存储后 9 局 6 次 MMU 故障。坑:1140
- **客体线程上的提交、出图入队、建 / 销贴图、svc 分发都包 autorelease pool**——对照仓显卡已退役未销毁 2.15 GB、每分钟涨 29 MB；判法 `SW_RES_CENSUS=1` 看斜率。同源:90
- **脏页 / 写追踪：先设只读，再比内容；遇页正被别的线程解保护（BUSY）等它落地**——次序反了 1 秒漏报 5–10 万次；另一种后果是 svc 读文件进只读页 EFAULT 读不全。坑:1970、同源:57
- **脏页跟踪表容量开到 4096，超限报红**（暗黑池峰值 7，大游戏远超 256）。同源:13
- **按地址反查内存池：先数池数**——池 3000+ 时线性扫 + 取锁每次绘制 99827→14294 条指令；暗黑 7 个池可以不改。同源:99
- **Ryujinx BufferCache 预扩前用 `vm_region_64` 核客体内存可读**——直通客体内存时未映射页是 PROT_NONE，1.5 倍预扩读到尾巴即 SIGBUS。坑:1960
- **内存判据用程序自己确定的量（malloc_zone_statistics、Metal currentAllocatedSize、资源计数），RSS 只报不判**——同提交两段 RSS 互差 >170 MB。坑:242
- **「开机起累计」的分配计数先比相邻两次差值，差 0 就是没发生**——曾据累计值排了一个无收益的根治项。活:84

## 七、iOS 真机差异（Mac 绿 ≠ 真机绿）

- **宿主运行时读的任何产物文件，先核 iOS 包有没有拷进去；能不按「文件在不在」分支就不分**——Mac 读产物目录、iOS 读包内拷贝，真机 0/3 进不了主菜单。坑:319
- **iOS 构建检查真编 + 真链（未定义符号即红），不只 `-fsyntax-only`**——`__builtin___clear_cache` 链不到，iOS 包全挂。坑:1906、坑:288
- **按名字找符号（dlsym）的机制先在真机验一次**——iOS 发布包主程序符号不进动态符号表，交替测量整轮开关没动、读数全 0。坑:518
- **测试设施一律显式开启；每加一个测试开关问「玩家路径下它是什么值」，冒烟至少一局不带任何变量 / 参数**——缺省看门狗 20 s 杀玩家、缺省模式是探针点图标即崩、拍入口钩子只在测试变量下挂。坑:354、坑:457、坑:526
- **新架构 iOS 三闸：确认日志有「libnxaot.a 已加载」（否则静默走回 HLE）、换掉 Ryujinx 彩色控制台 Logger、devicectl launch 的 env 不做 $DOC 替换（用相对路径）**。坑:1948
- **新包配同一产物根的资源分卷**——着色器库指纹不符返回 −10、host.log 0 字节，原因只在 unpack.log。坑:1964
- **Metal 4 只有 macOS / iOS 26+：对外写系统要求前用 `-mmacosx-version-min=15.0 -Wunguarded-availability -fsyntax-only` 列不可用接口；Info.plist 最低版本从 `otool -l` 的 minos 读**。坑:1770
- **iOS 上 abort 立即退出（5.2 s 出 SIGABRT 报告）；判局结束看崩溃报告 / host.log FATAL，别靠 devicectl 进程查询（30 s 超时返回空）**。坑:1909
- **发布包崩溃用同次构建 dSYM，按「pc 低 14 位 + lr−pc 差」反推函数（iOS 地址按 16 KB 随机偏移）**。坑:1943
- **GPU 故障的系统证据：Mac `/Library/Logs/DiagnosticReports/gpuEvent-*.ips`，真机 `idevicecrashreport -k -e`**。坑:1149
- **真机上永远不用 `devicectl copy to --remove-existing-content`，也不卸载 App 当「冷启动」**——清掉整个容器（Documents + Library，9 GB 资源 + Metal 缓存）；冷启动只清 Metal 缓存目录。坑:34、坑:270、坑:964
- **`devicectl copy from` 拉回后核字节数，0 字节重拉；不许用它轮询日志，读日志走 iproxy 日志口**——rc=0「File received」照样 0 字节。活:65、坑:1352
- **CoreDeviceService 首次拉文件 >60 s 就 `launchctl kickstart -k user/501/com.apple.CoreDevice.CoreDeviceService`**——退化到 200–265 s，重启后 10 s；xctrace 接不上同因。活:61
- **iproxy / 一切设备工具调用点名 UDID（`-u`），本机端口每次现取；UDID 取不到即停局**——并插两台时连到另一台；大写「UDID:」取空让白名单与功率采样静默跳过。坑:1559、活:73
- **跨进程 / 跨设备命令必须有回执**——发完 quit 即关连接，iproxy 拆连接与数据只差微秒，退出命令偶发丢。坑:375
- **真机容器会残留上一局产物：只拉本局 host.log 里确认生成的文件；存档指纹变了就重装**——旧 passgpu.tsv / 旧截图冒充本局。坑:1862、坑:1850

## 八、性能与功耗（测量口径）

- **计时局用 `conc_watch.sh` 每秒记并发宿主数，有并发的轮次作废**——Apple GPU 按利用率调频，别人同时跑时被测局反而快 35%（5.89 → 3.11 ms）。坑:112
- **串行化逐通道计时（PASSGPU_SERIAL）只看相对占比，绝对毫秒用不串行整帧读数**——串行让 GPU 空等降频；Mac 逐通道毫秒双峰、同设置差 10%，<10% 的着色器改动只能上真机。坑:112、坑:447
- **热态 <10% 的刀用同进程 300 帧窗交替开关（相邻窗配对取差），分段 ABA 只量 ≥10% 的大刀**——温控档 2 内功率预算分钟级持续下收，同为 A 的两段差 8–10%。坑:466
- **同进程交替里不混排近空载相；每轮报噪声底和相序**——空载相 GPU 闲 3 s 降频、后果滞后一相，曾被读成「丢界面 +38%」。坑:471
- **「GPU p50」是各命令缓冲时长之和，重叠 / 跨帧会重复计；过载时工作量读帧时间（1000/上屏帧率）**——3D 0.75 按 GPU p50 −10.6%，按帧时间 −24.1%。坑:470
- **跨包比较必须同一时段背靠背 A-B-A；温控档号相同 ≠ 热度相同**——同为档 2 差 10%，手机越烧越慢被读成「主干变快」。坑:563、坑:565
- **基准已顶 60 帧时同进程交替读不出差，量收益找 <60 的场景或改量功耗**。坑:564
- **真机 CPU 侧：指令数 / 绘制数降了 ≠ 省电；动手前先量上限（把那块活整个拿掉看瓦数动不动）**——小地图全关（绘制 1959→1152、指令 −27%）瓦数 4.00 vs 4.07 W 无差。坑:1109
- **真机 CPU 对照只认同核型内比较或整机瓦数**——主线程在 P/E 核间成块切换（76% vs 94% 在能效核），毫秒 / 周期 / 占用百分比跨局不可比；占用百分比还随主频漂。坑:1121、坑:1058
- **热状态 2 下系统把 USER_INTERACTIVE 线程也挪去能效核；真机读数报第 6 分钟后的热平衡段**——同绘制数显卡层 8.8→14.2 ms。坑:1962
- **.NET `Thread` 起的线程设不了 QoS（EPERM）；要 USER_INTERACTIVE 用原生 pthread 带 QoS 起再进托管**——未指定档的渲染线程一半时间落能效核。坑:1961
- **计时埋点在真机上不是噪声（GPU 线程 14%）；关计时后的 0 不等于没花时间**。坑:1963
- **整机瓦数遥测约每 20.4 秒成批进 20 样本：等一批进来再量下一整批，不混 40 / 60 次的格**——固定窗口同开法两轮差 1.2 W。坑:1427
- **挂着 Instruments 时只取份额，不取帧时间（采集进程占 4 个小核 36–47%，帧率 60→57.4）；录完核场景再读**。坑:511
- **远端构建机上逐编码器份额只是「谁在干活」的线索，结论要过一格真机同进程交替**——远端门禁机上 −2~3%，真机 +0.0%。坑:559
- **功耗读数先核窗口内实际渲染分辨率（过热会切掌机档）；帧率 > 刷新率等不可能值先追算式**。坑:391
- **提速请求先审视那一步要不要存在**——体检 dry-run 等于完整改写一遍（167 s）；zlib 候选一次喂 16 MB，抽取 288 s → 渐进喂 36.5 s。坑:1907、坑:1910

## 九、验证与调试方法

- **画面判据对模拟器真值（Ryujinx）同一状态截图，并配「非黑比例 / 网格亮度」这类抓整块缺失的粗判据**——只做宿主对宿主，3D 全黑、横竖屏错都「一致」。坑:38
- **到达判据必须是目标场景专属的量（进场景日志行、关卡号、截图地名），不用「负载够高 / 有字符行」；报读数前先看截图**——01006F8002326000卡标题「按 A」绘制 2000–4000 照样判到达。坑:1857、坑:1850、活:17
- **任何「等价 / 无差」判据上线前造一个必红的反例跑通；负对照漏抓必须判红**——尺子初版负对照大多判等价；equiv 变异漏抓只打印不判红。坑:432、坑:360
- **画面对比别只看全屏均值，加「大差像素数（任一通道 >30/255）」；同进程切换在切换点与取样点间留足帧；负对照选每帧被清的目标**——丢 FXAA 4051 个大差像素，FLIP 均值只 0.0016。坑:432
- **等价核对的比较点取被测方真正看到的值，不许为对齐而「修正」一侧状态**——fnfuzz 从栈上取回 x29 来比，把门块改坏 x29 盖住。坑:384
- **GPU 结果的参考实现用 CPU 按着色器数学直算（含存储格式量化），不用另一个手写着色器当真值**。坑:420
- **冻结帧不可复现先逐通道转储比 UBO：差在每帧全局常量里的帧号 / 时间相位 = 墙钟漏进来了**；`SW_DETCLOCK` 是每帧步长（写 16666667），写 1 = 时间几乎不走、按键被吞。坑:253、坑:1954
- **看「0 错」同时看这局跑满没有（帧数）；每次宿主改动的判据含「host.log 红行数」**——诊断函数自己崩、宿主提前退出，「错误行 0」被当成修好；旧路径带着 2669 行 Invalid Resource 没人看。坑:429
- **修复后端到端按全部错误类型核（ErrorHang + InnocentVictim + PageFault），别只看 Hang**——被连坐的局被误当不挂。坑:1971
- **诊断代码也是量具：写完拿一份真实栈数据手算核取址**——转储错一层帧指针，「为空 / 读不到 / 0xffffffff」全是错读。坑:842、坑:851
- **无进展看门狗触发时 dump 图形等待点状态（`mtl_wait_state_dump`：出图队列入/完成、主栅栏、节拍最后一次）+ 自采样**——两次直接定位真问题。坑:464
- **「偶发、无红行、只在本机」先查测量本身（共享脚本互删输出、并发），再查被测对象**——perdraw 输出目录写死、并行互删，被当卡死查两小时。坑:459
- **读日志先看行的先后，再下因果**——「audio 暂停（切后台）」排在「收到 quit」之后，曾被报成抢前台。坑:770
- **复现别人的路线环境一条不能删**——删掉后两段探路，A/B 全绿是假的。坑:1148
- **drawdiff「不确定·我方」先比参照哈希（diff.tsv 第 16 列）**——参照同样不定 = 苹果 GPU 共同不定，不是我方。活:94
- **客体线程（svc 门进宿主）上不做带 `%f` 的格式化打印，用 LOG / 原子计数**——客体栈小，打印栈溢出 SIGBUS，还会被误当证据。坑:259
- **`mtl_addr()` 返回的是 MTLBuffer 对象指针，读内容走 `.contents`**，直接加偏移读 SIGBUS。坑:257
- **怀疑「跟踪写坏数据」先跑「宿主不设页保护」对照**——进程内 CoreCLR 截走 Mach 异常、改坏叶子函数 x30；加载前 `PAL_MachExceptionMode=15` 并收回 SIGSEGV/SIGBUS。坑:1953
- **hostfxr 崩溃栈全是 JIT 地址时起局加 `DOTNET_PerfMapEnabled=1`，用 /tmp/perf-<pid>.map 翻名**。坑:1960
- **截图连拍间隔避开帧率偶数倍（0.3 s = 18 帧会全落在同一种帧上）**。坑:1452
- **Mac 开发局缺省必须等于产品配置（跟踪模式 precise、newarch.env 并进）；起跑核 stats.json 的 `track` 键**——一整夜 A/B 全在 all_dirty 下量，比例与产品不同。坑:1965、坑:1966
- **A/B 用同一份二进制切开关；核心库与 libnxgal 同提交编**——ABI 校验失败表现成 shader_miss 近千万，被当回归查半小时。坑:1967

## 十、工程与流程

- **NativeAOT：`[UnmanagedCallersOnly]` 必写 EntryPoint；判据 `nm -gU <库>.a | grep ' _ryu_'` 条数 = 入口数**——不写则整个 Ryujinx 显卡层被裁掉，库只剩 2.1 MB 空壳、编译照样成功。坑:1937
- **一个 iOS 进程只有一份 NativeAOT 镜像：由汇总工程一起 AOT，引用程序集的入口写 `UnmanagedEntryPointsAssembly`**。坑:1942
- **libbootstrapperdll.o 用 `ld -r -keep_private_externs` 和 NxAot.o 合成一个成员再打 .a**——直接链 .o 空程序 33 KB→17.5 MB，单独 .a 又不被拉进来、一调就崩。坑:1944
- **共享工具链（家目录下的 .dotnet）只读，装东西用独立 DOTNET_ROOT**；iOS NativeAOT 不需要 ios 工作负载。坑:1936
- **改写器生成的补丁块，除被改写指令的目的寄存器外，所有寄存器（含 x16/x17/x29/x18、NZCV）进出不变；跳板回 A+4；macOS 会把 x18 清零，客体 x18 全部换到线程槽**。坑:276、坑:384、坑:345、坑:1957
- **改写器换结构后核「控制流回到哪」，闸门覆盖平时不走的系统通知路径（运行中切掌机）**。坑:345
- **主干树只合并，各线在自有工作树开发与跑验收**——别线验收编进了他人半成品。坑:198
- **不改正在被执行的脚本 / 有局在用的树：bash 边读边执行；改脚本「写 .new → bash -n → grep 新关键字 → mv」一条命令；长跑从冻结的运行树跑，常驻循环每轮 `reset --hard` 到主干**。坑:418、坑:1923、坑:1927、坑:1888
- **注释只单独成行或放行尾，替换后干跑核最终产物**——塞进行中间吞掉同行后半截，`bash -n` 照过（一天三次，C 单测里也犯）。活:80、活:88、坑:1932
- **共享脚本凡写文件，输出路径按调用 mktemp 隔离并打印目录**。坑:459
- **构建产物里不含现场计时与输出目录绝对路径；判据：同提交两次出库逐字节相同**。坑:33
- **改 `.inc` 后 touch 主 .m 或补 Makefile 依赖**——nvn_rtex.inc 不被跟踪，make 报完成跑的是旧代码。坑:1445
- **改写器 / 生成器指纹变了要重出共享产物再合入**——patch_nso.py 改了、共享 rules 没重出，之后所有人合入都红。坑:1918
- **出包在临时 worktree 按指定提交出，包名与包内都写 9 位提交号，核它是主干祖先**——共享主树被切到别的分支，出了非主干包。坑:1890
- **同一目录反复装不同包要么 `--delete` 要么换新目录，同步前后各 `codesign -v`**——残留文件让签名失效，Mac 上 iOS 包被挪去随机只读路径运行，日志写不到。坑:1180
- **出包单独一条命令，看到成功行再跑测试**——编译失败后测的是旧包。坑:766
- **Mac 上跑 iOS 包：不在包运行中 / 刚杀完进程时换 `.app/Wrapper`（等挂载卸掉），不放 /private/tmp，同一 bundle id 只用一种签名**——失效挂载点只有重启能清；系统临时目录下进程停在 `_dyld_start`；签名身份不在容器 ACL 里弹框卡死 secinitd。坑:796、坑:1039、坑:1678、坑:1874
- **设备锁：构建在拿锁之前做；持锁期间每个 devicectl 带超时；持锁有上限（冒烟 600 s、测量 1200 s）；身份比对前 `LC_ALL=C`；设备互斥只认锁、不自己判「设备空闲」**。坑:341、坑:1352、坑:1307、活:69
- **每次重新拿到设备锁都重装自己的包，结果里记日志自报的版本特征**——段间让路时手机上已是别线的包。坑:523
- **本机同时最多 2 个宿主；验收整段持闸门锁；会制造 GPU 故障的实验只在无他人局时跑**——几套闸门并行内存耗尽内核崩溃；GPU 挂死实验连坐别人的局。坑:1290、坑:1973
- **远端构建机上开窗口 / 要显示刷新的任务只认一把锁**——新开窗口盖住别人，被盖窗口的显示节拍停、整局帧率 0。坑:1045、坑:1837
- **长跑用脚本 + `nohup … & disown`、`set -m` 自成进程组、按进程组停；报「在跑」前 10 秒内用 ps 核到进程号**——会话后台任务随会话被停、输出空却报在跑；只杀 bash 父进程，子进程成孤儿继续占机。坑:1389、坑:1416
- **等待进程结束用 `kill -0 <pid>`，不用 `pgrep -f <脚本名>`（会匹配等待命令自己）；每局新目录，等本局专属结束行**。坑:1928、坑:1935
- **本机计时一律 `mach_absolute_time`，计时类测量绕开终端 QoS 封顶（guirun）**——cntvct 换算错，把 0.12 ms 测成 5–8 ms。坑:34
- **现役数据（闸门真值、前缀）放 data/ 下带 README 的只读目录；清理前 grep 引用**——整目录 rm -rf 让主干合入全面停摆。坑:1975
- **commit 前必看 `git show --stat`（无二进制 / dSYM、无 0 文件空提交）；压缩提交用 merge-base 做基点**——`git add -A` 带进单测产物；`reset --soft sw/main` 把别人的提交回退进主干。坑:325、坑:557
- **会上传 / 发布的命令，跑前 grep 到防护开关那一行真在脚本里**——开关没写进去就跑，误传 TestFlight。坑:1602

## 最值钱的 10 条（新游戏第一天就要知道）

1. **Metal 4 不自动驻留：资源在创建处登记驻留集，改存储对应关系必跑 `SW_RES_CHECK=1`**——首传漏登 = 每次提交 GPU 地址页错误；对调存储 = 9 局 6 次 MMU 故障。坑:425、坑:1140
2. **未实现的 NVN 入口首次被调必报红，用全量日志 0 条证明不踩；静默路径（线性贴图建成空贴图）才是雷**。同源:39、同源:44
3. **假冒 NVN 结构 `_Static_assert(sizeof ≤ 真结构)`；老 SDK 两个 Acquire 入口都要接；跨语言枚举按值换算**。坑:1955、坑:1956、坑:1946
4. **跨线程的 Metal 编码器加所有者断言；出图路径改动用 `SW_WINDOW=1` 验——Mac 无窗口对出图线程是盲的**。坑:230
5. **节拍驱动出图必须有兜底：DisplayLink 停 0.5 s 自取 drawable；进后台先清排队帧**——否则画面定格 / 存盘 0 次。坑:1844、坑:1016
6. **掉帧只认实际上屏间隔；换出图路径后先用已知有差的开关验量具**——游戏循环会与上屏解耦恒 16.67 ms。坑:336、坑:484
7. **着色器缓存三件套：种子按首次使用顺序、真机录（配置与包一致）、iOS 库收归档且按 iOS 大版本出；判 `shader_miss = 0`**。坑:524、坑:1949、坑:1938、坑:1941
8. **Mac 开发局缺省必须等于产品配置（precise 跟踪、newarch.env）；测试开关显式开启，冒烟至少一局玩家路径**——否则整夜 A/B 白量、玩家点图标即崩。坑:1965、坑:354、坑:457
9. **性能读数：并发 / 温控 / P-E 核切换都会骗人；<10% 的刀只用同进程交替，CPU 侧先量上限看瓦数**——指令 −27% 瓦数不动。坑:112、坑:466、坑:1109、坑:1121
10. **判据先造必红反例；到达用场景专属量；「0 错」同时核跑满与 host.log 红行**——尺子负对照判等价、标题画面判到达、诊断自崩当修好，三种绿着失效都真实发生过。坑:432、坑:1857、坑:429
