# 排查步骤

所有门槛与出处见 [排查手册](../../../docs/排查/帧率低与耗电高.md)；下面只写顺序、要跑的命令和怎么读结果。命令都在仓库根目录跑。

## 第 1 步：快检 + 局有效性

```sh
python3 tools/quality_check.py <局目录> --report <报告目录>   # 判官用自己的模型；都没有才加 --no-ai
python3 tools/score_cells.py <局目录> --game=<款> --commit=<包提交> --diag=1
```

- 快检一行九列：款 / 画面 / 帧率 / 满屏 / 直连默认启动 / 能耗 / 读数 / 截图 / 局目录。没有看图判官（或加了 `--no-ai`）时画面、直连默认启动两列写「没数据」，原因看读数里的「AI 判官失败：…」。
- `score_cells` 标准输出一行（记分板行），标准错误逐格 `# <格> <值>（<说明>）`。读数以【局无效】开头 → 停：报无效原因（手册 ③ 1 的四类），不下帧率 / 能耗结论。
- 读数以【未满屏，读数不作数】开头 → `score_cells` 帧率 / 能耗两格「未测」，快检照判；两边都报，注明未满屏。

## 第 2 步：帧率分支（帧率列「不过」或「没数据」）

| 先看 | 判别 | 下一步 |
|---|---|---|
| `score_cells` 帧率说明里「窗口不足 55 秒」或「没到 MARK」 | 窗口无效，不是帧率问题 | 报「没数据」与原因 |
| `python3 tools/game_fps.py <局目录>` 的说明列 | 目标是不是调用方以为的帧率（30 / 60），按哪一步定的 | 想要 60 但目标 30 → 第 4 步 |
| 帧率说明里「平均 x 帧/秒」与「慢帧 y%」 | 平均 < 目标 × 0.99 还是慢帧 > 1% | 跑手册 ② 的慢帧清单 |
| 慢帧清单逐帧 | 按手册 ③ 4 的对照表归到：首遇（`xlate_n` / `pso_n` / `shader_miss`）、宏（`macro_us`）、读回（`rb_us`）、GPU 反压（`gpuq_us`）、GPU 时间（`gpu_us`）、GC（`gc_pause_us`）、都不高 | 报每类几帧、举 1–3 个帧号 |
| `python3 tools/frame_gate.py <局目录>` | 分配 / GC / 读回闸门：绿 / 红 / 未测 + 说明 | 红 → 报说明原文 |

## 第 3 步：能耗分支（能耗列「不过」或「没数据」）

| 先看 | 判别 | 下一步 |
|---|---|---|
| 局目录有没有 `pwh.plist`、`pw1.plist` | 缺 → 没数据。Mac 局不采；真机局代码里的缺因：没装 libimobiledevice（`tools/dev_run.sh` 第 262 行）、没到 MARK 就不采 `pwh`（第 411 行）、测试段剩不到 25 秒不采 `pw1`（第 451 行） | 报缺哪个 |
| 帧率格 | 帧率格未测 → 能耗不判；帧率格红 → 能耗不过（「帧率未保持」） | 先走第 2 步 |
| 读数里的瓦数与门槛 | 目标 ≥ 59 帧对 4.8 W，其余对 3.7 W | 报瓦数、门槛、差值 |
| 读数括号里的状态 | 「充电状态·热档位」，只标不挡判 | 照抄进结论 |
| 局数 | 单局不可信，至少 3 局中位；A/B 要 B − A 超过 `tools/ab_noise.tsv` 的噪声底 | 少于 3 局时结论标「单局，暂定」 |
| `host.log` 的 `[能耗]` 行（每 10 秒） | 性能核 / 能效核瓦数、耗能前 6 线程 | 按手册 ③ 6 的表从第 1 行往下对 |

## 第 4 步：60 帧分支（目标 30 但要 60，或 60 帧开了没效果）

按手册 ③ 3 的判别步骤在 `host.log` 里找行，第一处命中就停：

1. `能力清单：60 帧关` / `帧率表 …：60 帧关` → 开关关着。
2. `【红】帧率表 … 整表不用` → 构建号不配，转第 5 步的跨版本。
3. `帧率表：热状态严重…` / `帧率表：低电量模式开着…` → 自动降档。
4. 没有任何「帧率表」行、没有 `社区补丁：帧率类 N 份跟 60 帧开关 开`、直连 `present tick` 行也不是 `interval mode display` → 这款没有放开 L1 的手段，L1 缺。
5. 帧节拍最后一行交换间隔 2，直连 `present tick` 行 `interval mode game` → L1 没放开。
6. 帧率表行「出图间隔放开」或 `interval mode display`，实测平均仍约 30 → L2；查 `tools/fps_truth.tsv` 本款程序号。
7. 实测到 60 → 转第 5 步验逻辑速度（L3）。

## 第 5 步：逻辑速度与跨版本

```sh
python3 tools/fps_speed_judge.py <关局目录> <开局目录>
python3 tools/fps_relocate.py <旧版 exefs/main> <新版 exefs/main> runtime/fps/<旧构建号前 16 位>.tsv
```

- `fps_speed_judge` 退出 0 绿 / 1 红 / 2 判不出 / 64 用法错；最后一行 `判定：…` 原样引用，射程（配对几条、q 多少）照抄。
- `fps_relocate` 退出 0 可带用（候选表打到标准输出）/ 1 不能带用（原因在 🔴 行）/ 2 参数或读文件错。

## 输出格式

先一句结论（过 / 不过 / 没数据 / 局无效，卡在哪一处），再一张对位表，最后列没跑的和下一步：

| 项 | 期望 | 真结果 | 证据（命令输出行或日志原行） | 出处 |
|---|---|---|---|---|
| 平均帧率 | ≥ 目标 × 0.99 | … | … | `tools/score_cells.py` 第 163 行 |
| 慢帧 | ≤ 1% | … | … | 同上 |
| 整机功率 | ≤ 4.8 / 3.7 W 且帧率格绿 | … | … | `tools/score_cells.py` 第 166、208–211 行 |

射程写清：窗口帧数、局数、配对数。没跑的项写「没跑：跑 X 才知道」。
