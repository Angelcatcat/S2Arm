# 数值先判，视觉后判

数值由生产者对全部关键帧、连续帧、MARK 成对计算，取最差值，不能只测一帧。缺失、非有限数、单位不符直接报输入错误；任一不过不调用 CLI（包括认证查询）。

| 数值字段 | 通过门槛 | 口径与来源 |
|---|---|---|
| hole_side_fraction_max | ≤0.005 | 露空占两侧新增带的比例，非全图比例。沿用 graphics/widen/README.md、closed_loop.sh 与 tests/visual/widen_holes.py 的地面行口径 |
| center_psnr_db_min | ≥30 dB | 中间 16:9 与原图同高度，不做拟合/重缩放。沿用 tests/visual/widen_cmp.py 默认门槛，零误差有限值用 999（该工具也接受现有99） |
| ui_width_ratio_min/max | 调用方确认的 1±tolerance | 各可匹配界面元素宽度比的最小/最大值，wide/orig；画幅线已确认容差0.04，依据及来源见下文；必须显式外置策略，缺则拒绝 |
| ui_height_ratio_min/max | 调用方确认的 1±tolerance | 高度比，wide/orig；同上。没有可匹配 UI 不能填 1 代替证据 |
| flicker_excess_luma_max | 调用方确认的上限 | 相邻帧平均归一化亮度变化的额外量：max(0, abs(Lwide[t]-Lwide[t-1])-abs(Lorig[t]-Lorig[t-1]))，两秒窗口取最大；画幅线暂取2/255，待真实露台录像校准；必须显式外置策略，缺则拒绝 |

[画幅线评审](https://github.com/jhaizhou-ops/S2Arm/pull/180#issuecomment-6380574089) 已确认外置策略及UI容差0.04（其怪猎obj_scale测量误差最大约3.5%，非本Server实测）；闪烁2/255仍为临时值，basis须注明临时，待真实录像校准。消费者没有默认通过阈值。`--policy` 是调用方明确选择的已确认策略（必须在证据目录之外，绝不能让输入素材自行设门槛）；没给则拒绝，合成测试策略仅用于测试、不代表产品认可。全局均值会漏掉局部闪烁/小图标错位，必须继续看图。此轮只实现消费者，不改闭环出图、不重定义第二层出表成功。

| JSON checks 键 | 逐图/逐帧审查 |
|---|---|
| stretch | 圆形仍圆，人物/物体与文字宽高比不变；两侧是新增视野，不能整图横向拉伸 1.22 倍 |
| alignment | 中间 16:9 场景对应原图中心，界面/锚点位置一致，无平移、重复、断裂或层间错位 |
| ui_bounds | 原界面可见、原尺寸居中，无裁切、越界、重叠或面板中心漂移 |
| bright_bands | 原16:9边缘及新增区没有阶梯亮带、压暗断层、接缝或异常色条 |
| flicker | 逐一看完整连续帧，不漏掉隔帧变化；相对原图无新增闪烁、光影跳变、交替残影 |
| side_content | 两侧外延与中间场景透视、纹理、遮挡、亮度连贯；不接受镜像、空洞、复制带或无根据的填充 |

每项理由说明看到了什么，不能只说“数值通过”。缺细节、无法看清、图像工具失败或上下文不足，标为不确定，不猜通过。
